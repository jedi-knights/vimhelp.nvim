1. Introduction                                                *vimhelp-intro*

vimhelp.nvim wires the |vimhelp-index| CLI into Neovim: full-text search
over |:help| that finds the doc you need without knowing the exact tag.

The plugin is a thin shim — it invokes the vimhelp-index binary as a
subprocess, parses the JSON response, and renders ranked hits. The
heavy lifting (tantivy index, BM25 scoring, snippet highlighting) lives
in the CLI.

==============================================================================
2. Requirements                                         *vimhelp-requirements*

- Neovim 0.10+.
- The `vimhelp-index` binary on `$PATH`, or a `binary_path` set via
  |vimhelp-setup|. Install from:
  https://github.com/jedi-knights/vimhelp-index/releases
- An index directory built by `vimhelp-index build`. Default location:
  `stdpath("cache") .. "/vimhelp-index"`.
- Optional peers: `folke/snacks.nvim` or `nvim-telescope/telescope.nvim`
  for an interactive picker. Without either, |:VimHelpSearch| falls
  back to a plain |:messages| render — no error.

==============================================================================
3. Setup                                                       *vimhelp-setup*

setup() is optional — defaults ship in config.lua and the |:VimHelpSearch|
command works with no configuration when vimhelp-index is on PATH and
the default index directory exists. Call setup only to override defaults.
>lua
    require("vimhelp").setup({
      binary_path = "/opt/homebrew/bin/vimhelp-index",  -- override PATH lookup
      index_dir   = vim.fn.stdpath("data") .. "/help-index",
      limit       = 10,
    })
<

4. Commands                                                 *vimhelp-commands*

------------------------------------------------------------------------------
4.1. :VimHelpSearch                                         *:VimHelpSearch*

>
    :VimHelpSearch {query}
<
Search the vimhelp index for {query} and open the configured picker
(or fall back to |:messages|). Multi-word queries work:
`:VimHelpSearch floating window` is a single query, not two.

Picker resolution order under the default `picker = "auto"`:
  1. `folke/snacks.nvim` if loadable
  2. `nvim-telescope/telescope.nvim` if loadable
  3. Plain :messages render

Force a specific backend via |vimhelp-config|'s `picker` key. Non-
`"messages"` values silently fall back to `"messages"` when the
requested peer isn't loadable, so `:VimHelpSearch` never errors just
because a picker isn't installed.

On selection:
  - Hit has `tag` → `:help <tag>`.
  - Otherwise → `:edit <document>` and cursor to `line`.

Rejects an empty query with an actionable message. Errors clearly if
the binary is missing (points at the install URL) or the index
directory doesn't exist (points at the build command).

Example messages output (fallback): >
    1. nvim_open_win  (score 3.42)
       $VIMRUNTIME/doc/api.txt:1287  — 3.2. Window functions
       Opens a new floating window. Windows attach to a buffer …

    2. wincfg-title  (score 1.85)
       ...
<

------------------------------------------------------------------------------
4.2. :VimHelpHover                                          *:VimHelpHover*

>
    :VimHelpHover
<
Grab the word under the cursor (|<cword>|), run a `--limit=1` search,
and jump straight to the top hit. Skips the picker on purpose — hover
is a one-keystroke "go to the doc" gesture; explore alternatives via
|:VimHelpSearch|.

Landing behaviour (from |vimhelp.jump|):
  1. Try `:help <tag>` when the hit has a tag. Nicer UX when the tag
     is discoverable on |runtimepath|.
  2. On `:help` failure (typically |E149| when the indexed corpus
     lives outside runtimepath), fall through to
     `:edit <document>` + cursor at `line`.

Users typically bind to |K|:
>lua
    vim.keymap.set("n", "K", require("vimhelp").hover,
      { desc = "vimhelp hover" })
<
The plugin does NOT auto-map |K| — it's already claimed by LSP hover,
filetype-specific handlers, and user configs.

Every hover failure mode (no word under cursor, missing binary, missing
index, zero hits, non-zero subprocess exit) surfaces as a |vim.notify|
line, never a Lua traceback. Safe to bind directly.

==============================================================================
5. Configuration                                             *vimhelp-config*

Defaults (see `lua/vimhelp/config.lua`):
>
    {
      binary_path = nil,     -- nil probes $PATH for "vimhelp-index"
      index_dir   = stdpath("cache") .. "/vimhelp-index",
      limit       = 20,      -- 0 means the CLI's default cap
      picker      = "auto",  -- "auto" | "snacks" | "telescope" | "messages"
    }
<

==============================================================================
6. API                                                         *vimhelp-api*

Submodules (`require("vimhelp.<name>")`):

- `config`             — defaults and merge helper.
- `binary`             — subprocess invocation (`resolve`, `search`).
                          Injectable `runner` for tests.
- `search`             — pure `parse` + `render` for the CLI's JSON
                          envelope.
- `picker`             — dispatcher (`choose`, `pick`) that routes a
                          parsed result to a picker backend.
- `pickers.snacks`     — snacks.nvim adapter.
- `pickers.telescope`  — telescope.nvim adapter.
- `pickers.messages`   — plain-messages fallback.
- `jump`               — `to_hit(hit, deps?)`: `:help <tag>` when the
                          hit has a tag, else `:edit <document>` +
                          cursor at `line`.
- `health`             — |:checkhealth| entry point.

Facade (`require("vimhelp")`):

- `setup(opts?, deps?)`   — merge opts over defaults; optional.
- `search(query, deps?)`  — resolve binary + run subprocess + parse +
                             route to picker. Throws on failure (the
                             |:VimHelpSearch| command wrapper pcalls
                             it). Returns the raw parsed result.
- `hover(deps?)`          — `<cword>` → `--limit=1` search → jump.
                             Never throws (safe to bind to a keymap
                             directly). Returns the raw parsed result
                             when a jump happened, nil otherwise.

==============================================================================
7. Health                                                    *vimhelp-health*

Run `:checkhealth vimhelp` to verify:

- The plugin loaded and the detector permits execution.
- `vimhelp-index` is discoverable on PATH (or at the configured
  `binary_path`).
- The configured `index_dir` exists.

Both binary-not-found and index-not-found surface as actionable health
reports pointing at the install URL and the build command respectively.
